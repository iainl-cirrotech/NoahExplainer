Business Central AL agent harness

Noah

A minimalist, developer-centric agent harness: a thin streaming wrapper around an LLM that assembles context, runs tools, and writes reviewed changes.

What it is
  • A C#/.NET 10 CLI built around one streaming agent loop.
  • Four ways to drive it: interactive TUI, JSONL, JSON-RPC over stdio, or an in-process SDK.
  • Provider-neutral: OpenAI-compatible, Azure, Anthropic, Gemini and Ollama behind one ChatMessage model.
  • Primitives, not features: capabilities are tools, skills and extensions, never baked into the core.
Why it was created
  • A chat window alone makes you the integration layer: paste context in, copy answers out.
  • No file access, no ability to build or test, no memory between sessions, no repeatable workflow.
  • Noah closes that gap while staying small, transparent and inspectable.
Problems it solves
  • Context engineering: system prompt, AGENTS.md, skills and history assembled automatically each turn.
  • Tool access: read and write files, run shells, search symbols, review diffs.
  • Memory: branchable session trees, persisted and compacted as they grow.
  • Review boundary: changes proposed as VS Code diffs, never silently applied.
  • No lock-in: swap models or vendors without changing your workflow.
Business Central tooling
  • 16 AL tools including al_init, al_project, al_objects, al_build, al_test and al_audit.
  • Specification-first: scope questions, then extension-spec.md and an implementation plan.
  • Symbol search across project source and downloaded dependencies through the AL language server.
  • Evidence: Microsoft Learn citations, compiler diagnostics and a verification report.
  • Safe boundary: it never publishes, installs or upgrades an environment without an explicit request.
